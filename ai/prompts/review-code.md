# Revisar código

## Entrada

- Requisito relacionado: `<RF-XXX>`
- Cambio: `<descripción o Pull Request>`

## Revisar

1. Cumplimiento de requisitos.
2. Criterios de aceptación cubiertos.
3. Tests apropiados y significativos.
4. Reglas de negocio.
5. Seguridad y ausencia de secretos.
6. Separación de responsabilidades.
7. Compatibilidad con el código existente.
8. Complejidad y dependencias innecesarias.
9. Documentación afectada.

## Salida

Clasifica los hallazgos como:

- CRÍTICO
- IMPORTANTE
- MENOR
- SUGERENCIA

No rechazar una implementación solamente por preferencias de estilo si no existe una regla documentada.
